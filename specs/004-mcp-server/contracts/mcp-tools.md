# Contract: `drut-mcp` MCP Tools Surface

`drut-mcp`'s contract with any MCP client — the four tools it exposes, their
input/output shapes (data-model.md §2–§6), and per-tool behavior. Not
VS-Code-specific or even editor-specific (constitution Principle VI's spirit
applies here too, even though this isn't an LSP capability): any MCP-capable
client gets the identical contract.

## Transport & capability advertisement

Stdio only (`transport-io`, research.md §1's Assumptions), launched as `drut
mcp` with no flags — the same "no configuration beyond pointing a client at
this binary" shape `003-lsp-vscode-extension/contracts/extension-manifest.md`
already established for `drut server`. Tool listing (`tools/list`) and schemas
are generated by `rmcp`'s `#[tool]`/`schemars` machinery (research.md §1/§3)
directly from each tool's Rust input struct — never hand-maintained
separately from the code that implements it.

## `diagnose` (FR-003)

- **Input**: `DiagnosticsInput` (data-model.md §3).
- **Output**: a list of `DiagnosticDto` — every reachable diagnostic category
  for the given source, exactly matching `voyager-core::parse`/`parse_bytes`'s
  own output (never a narrowed subset).
- **Empty input, empty result**: an empty script produces an empty diagnostic
  list, not an error (Edge Cases: empty input is valid input).

## `format` (FR-004, FR-005)

- **Input**: `FormatInput` (data-model.md §4).
- **Output**: `FormatResultDto` — reformatted text, `changed`, and
  `encoding_fidelity`, always all three together (never text without
  `changed` — FR-004's whole point is letting a caller skip its own
  byte-comparison).
- **Idempotence carries through unchanged**: feeding a `format` result's own
  `text` back in as a fresh `text` input produces `changed: false` — inherited
  directly from `voyager_core::format`'s own guarantee (constitution
  Principle III), not something this tool re-verifies or could break.

## `query_structure` (FR-006, FR-007)

- **Input**: `StructuralQueryInput` (data-model.md §5) — a `ScriptSource` plus
  a 1-based `line`/`column`.
- **Output**: `BlockInfoDto` (data-model.md §5), always present as a
  successful result even when `kind` is absent (FR-007 — "no enclosing block"
  is data, not an error).
- **Out-of-range position**: clamps to the nearest valid position before
  resolving (Edge Cases), the same no-panic discipline
  `contracts/block-resolution-api.md` requires of `block_at` itself.

## `lookup_keyword` (FR-008, FR-009)

- **Input**: `KeywordLookupInput` (data-model.md §6) — `enclosing_control_word`
  and/or `spellcheck_token`, independently optional.
- **Output**: a list of `KeywordCandidateDto` (present whenever the caller's
  intent includes candidate listing — i.e., whenever this tool is called at
  all, since `enclosing_control_word: None` is itself FR-008's valid
  general-syntax-fallback request) plus an optional `SpellCheckSuggestionDto`
  (present only when `spellcheck_token` was supplied).
- **Exact match needs no correction**: a `spellcheck_token` that already
  exactly matches a real keyword yields `suggestion: None` — nothing to
  correct is itself a meaningful, successful answer (mirrors `did_you_mean`'s
  own existing contract exactly, `contracts/keyword-dictionary-api.md`).

## Error handling (FR-002, FR-010, FR-012)

- **`ScriptSource` with both or neither of `text`/`path` set**: every tool
  returns a structured tool-call error naming the problem plainly — never a
  silent default, never a guess at which one the caller "probably meant."
- **A `path` that doesn't exist or isn't readable**: a structured error, not a
  panic and not a result indistinguishable from "the file parsed clean."
- **No tool ever writes to disk, under any input** (FR-010) — every tool's
  only effect is the value it returns; verified directly by exercising every
  tool against a read-only fixture directory in this feature's own test
  suite (quickstart.md).
- **No panics on any input, structurally malformed or otherwise** (FR-012) —
  inherited from `voyager-core`'s own crate-wide no-panic guarantee for
  every code path this server calls into; this contract adds no new
  failure mode beyond "return a structured error instead."
